## 3. 变更内容（decision-complete，**全部为"追加/标注"，零删除**）

### 3.1 新增「B 类分类台账总表」（Part 3 开头，`### 3.1` 之前）

在 Part 3 标题下插入一张 **79 行**总表（§8 报告的机读版）：

| 列 | 说明 |
|---|---|
| 条目 | `B-01`…`B-79` |
| 原编号 | 如 `F-02` |
| **分类** | `[ACTION]`／`[BLOCKED-真机依赖]`／`[BLOCKED-越界]`／两者兼有 |
| 判据 | 一句话（引 `§0.1` 的具体红线条目 或"需真机会话"） |
| 方案三要素齐备 | `✅`／`❌（本次补全）` |

### 3.2 每个 B 条目追加一行「分类标注」（**不改原文一字**）

在每条的 `> 规则：…｜ 批次：… ｜ 判定：…` 行**之后**追加一行：

```
> **分类：`[ACTION]`（或 `[BLOCKED-真机依赖]`／`[BLOCKED-越界]`／兼有）｜ 判据：…（引 §0.1 或"须真机会话"）｜ 真机依赖：是/否 ｜ 越界点：…或无 ｜ 已覆盖：…或无**
```

### 3.3 `[ACTION]` 条目的「方案补全」（仅当缺三要素时追加）

缺"修改位置／修改逻辑／预期结果"的，在该条**`#### 3. 修改方案` 末尾追加**（**不改原内容**）：

```
> **[方案补全·ACTION]**
> - **修改位置**：`路径::函数/位置`
> - **修改逻辑**：一句话（可判定的动作，禁"酌情/优化"类模糊表述）
> - **预期结果**：可观测的判据（如"该表仍成功导入且报告含 1 条"）
```

### 3.4 「真机依赖」条目的处理（＝人工裁定①的口径）

- **不删除**原条目任何文字；
- 仅追加 `> **分类：`[BLOCKED-真机依赖]` ｜ 判据：其验证须真机会话（Qt/窗口/线程运行期行为），Agent 无真机环境**`；
- 并在**总表**中列为"移出施工清单"。
- ⇒ 结果：施工清单**不再包含**这些项，但**原文证据完整保留**（可回溯"为什么当初不做"）。

### 3.5 明确「零代码」

- **本次不改任何源码**；`git status` 的源码文件集**应保持不变**（除 `_temp/ImportData/plan.md`）。
