## 1. SQLite Rules

### 1.1 核心规则

1. 所有多表关联必须使用 SQL `JOIN`，禁止 Pandas `merge`
2. 条件统计必须使用 `GROUP BY`，禁止加载全表后 `groupby()`
3. 禁止 `SELECT *`，必须显式列出所需字段（详见 Pandas Rules）
4. 数据量 > 10万行时，禁止将结果加载到 Pandas，应在 SQL 中完成聚合
5. SQLite 连接必须开启 WAL 模式
6. 写操作必须包裹在事务中（`conn.commit()` / `conn.rollback()`）
7. 任务结束后清理 `.db`、`.db-wal`、`.db-shm`
8. 步骤不得自行创建 SQLite 连接，必须使用引擎传入的共享连接

### 1.2 SQLite 决策树

```text
需要多表关联？ → SQL JOIN
需要条件筛选？ → SQL WHERE
需要聚合统计？ → SQL GROUP BY
需要排序/去重？ → SQL ORDER BY / DISTINCT
以上都不是，且数据量 < 200万行？ → Pandas
以上都不是，且数据量 ≥ 200万行？ → 重新审视需求，大概率应在SQL中完成
```

## 2. Pandas Rules

### 2.1 使用条件

1. 仅当 SQL 无法实现时使用 Pandas（复杂字符串处理、自定义业务公式、透视表等）
2. 输入数据必须 **≤ 200万行**，超过必须先在 SQLite 中聚合
3. `pd.read_sql()` 必须指定 `dtype`，禁止 `SELECT *`
4. 处理完毕必须 `del df` + `gc.collect()`
5. 超过100万行的 Excel 必须 `chunksize` 分块读取并追加写入 SQLite
6. 禁止在 Pandas 中做多表 `merge`（应在 SQL 中 `JOIN`）

### 2.2 Pandas Red Lines（绝对禁止）

- ❌ `pd.read_sql("SELECT * FROM ...")`
- ❌ 未指定 `dtype` 加载大表
- ❌ 在 Pandas 中执行 `groupby().agg()` 替代 SQL `GROUP BY`
- ❌ 在 Pandas 中执行 `merge()` 替代 SQL `JOIN`
- ❌ 将 > 200万行数据加载到 DataFrame

### 2.3 内存安全

1. `pd.read_sql()` 必须指定 dtype（如 `{'id': 'int32', 'amount': 'float32', 'status': 'category'}`）
2. ETL 各阶段完成后必须 `del df` + `gc.collect()`
3. 进入 Pandas 的 DataFrame 不超过 **200万行**
4. 使用 `psutil` 在关键节点记录内存占用，超过阈值（如12GB）记录 WARNING
5. 任务结束后清理 `.db`、`.db-wal`、`.db-shm`（防止临时文件残留）

## 3. Output Rules

| 输出类型 | 规则 |
|---------|------|
| **Excel** | 严禁 `df.to_excel()` 裸导。必须 `openpyxl.load_workbook(template)` 加载模板 → 逐行填入数据 → `save()` |
| **Word** | 使用 `python-docx` 基于模板替换占位符（`{{placeholder}}`）——**v3.1 无对应用户操作（能力缺口/预留）** |
| **TXT** | 标准 `open()` 写入，指定编码 `utf-8`——**v3.1 无对应用户操作（能力缺口/预留）** |
| **PPT** | 预留接口（`export_ppt`），当前抛出 `NotImplementedError`——**v3.1 无对应用户操作（能力缺口/预留）** |

> **现行口径（2026-11-01 裁定）**：`ops/exporter.export_table` 使用 `Workbook(write_only=True)` **流式直出、无模板**；"Excel 模板填充"仅作**目标态**保留，**模板化输出暂缓**（W-24 已裁定关闭，不阻塞交付）。原文所述 `openpyxl.load_workbook(template)` 当前**未采用**。
>
> 所有输出模板文件存放于 `templates/outputs/`，由业务人员预设，代码中只引用路径。
> **2026-10-24 注记**：`templates/outputs/` 现仅留 `.gitkeep`（占位模板已于 2026-09-14 宣布清理失效）；`templates/user/` 为用户配置模板目录（运行时创建）。Word/TXT/PPT 三类输出在 v3.1 均无对应用户操作，相关依赖已移除（见 §7）。

## 4. Error Handling

1. 所有 SQL 操作必须包裹在 `try...except` + 事务中
2. 文件读写操作必须捕获 `FileNotFoundError`、`PermissionError`
3. 异常策略由参数文件 `on_error` 字段控制：
   - `stop`：记录ERROR → 终止工作流
   - `skip`：记录WARNING → 跳过当前步骤继续
   - `retry`：重试 `retry_count` 次 → 仍失败则终止
4. 禁止裸 `except:`，必须指定异常类型
5. 异常信息必须包含：步骤ID、步骤名称、异常类型、异常消息

## 5. Logging Requirements

- **全局统一日志（总则）**：整个引擎的所有模块（`main.py`、`engine/` 等）必须共享**同一个** loguru 全局 logger 实例；日志配置（级别、输出路径、轮转策略）仅在应用入口**集中初始化一次**（现位于 `gui/app.py` 的 `_setup_gui_logging`；原 `main.py` 的 `_setup_logging` 已随 CLI 移除）；各模块统一通过 `from loguru import logger` 获取同一实例，**禁止**在模块内自行创建独立 logger 或重复配置 handler
- 使用 `loguru` 记录日志 `[注：经人工裁决，print用于终端即时调试，logging用于持久化记录，二者共存，不互斥]`（GUI适配：print 输出经 loguru 落盘 logs/ 文件——GUI 终端面板已随 W-19 移除（2026-09-18）；用户交互界面只显示关键信息——步骤名称、状态、结果，不直接展示 print 内容）
- 日志级别：
  - `INFO`：流程节点（步骤开始/结束、耗时、处理行数）
  - `WARNING`：脏数据跳过、非致命异常
  - `ERROR`：系统异常、步骤失败
- 日志内容必须包含：工作流名称、步骤ID、处理耗时、处理行数、内存占用峰值（`psutil`）
- 日志文件输出至 `logs/` 目录，按日期滚动

## 6. Anti-Patterns（禁止模式）

| ❌ 禁止 | ✅ 正确 |
|---------|---------|
| 在 `engine/executor.py` 中写 `if step_type == "xxx": do_something()` | 经 `ops/step_executor.execute_step()` 查 `BUILTIN_OPS` 目录分发（v3.1） |
| 操作函数中 `sqlite3.connect("my.db")` 自建连接 | 使用 `execute(params, db_conn)` 中传入的 `db_conn`（连接由 `ops/session_db.SessionDB` 统一创建） |
| `df.to_excel("output.xlsx")` 裸导 | `openpyxl.Workbook(write_only=True)` 流式直出（现行 `ops/exporter.export_table`，无模板；模板化为目标态且暂缓，见 §3 与 W-24） |
| `pd.read_sql("SELECT * FROM big_table", conn)` | `pd.read_sql("SELECT col1, col2 FROM ...", conn, dtype={...})` |
| 在 Pandas 中 `df1.merge(df2, on="id")` | SQL `SELECT ... FROM t1 JOIN t2 ON t1.id = t2.id` |
| GUI 中直接调用 `ExtractExcelStep().execute(...)` | GUI 生成 JSON → 引擎读取执行 |
| 在 `main.py` 中硬编码 `steps = [step1, step2, step3]` | 从 JSON 参数文件动态加载步骤列表 |
| 步骤间传递 `df` 对象 | 步骤间通过 SQLite 表名传递 |

## 9. 函数结构规范（历史提示词提炼）

### [14] 每个独立功能必须封装为独立的函数或类
- **优先级**: 🔴 强制
- **要求**: 每个独立功能必须封装为独立的函数或类，禁止将多个不相关功能混入同一函数
- **正例**: v3.1 用户操作封装为 `ops/` 下的独立操作函数，并在 `BUILTIN_OPS` 登记；工具逻辑封装为独立函数
- **反例**: 将读取、清洗、计算、导出等不相关逻辑全部堆砌在一个函数中
- **来源**: 历史提示词提炼（T1-T48，48/48；语义经人工裁决修正）

### [15] 函数必须有明确的命名
- **优先级**: 🔴 强制
- **要求**: 函数必须有清晰、语义化的命名，禁止匿名式或占位式命名

- **来源**: 历史提示词提炼（T1-T48，48/48）

- **来源**: 历史提示词提炼（T1-T48，≥45次）

## 11. 异常处理补充规范（历史提示词提炼）

> 与 §4 的关系：本节为函数级异常处理的补充约定；v3 步骤实现必须同时满足 §4（禁止裸 except、异常信息含步骤ID 等）。

### [4] 函数整体必须包裹 try-except 结构
- **优先级**: 🔴 强制
- **要求**: 函数操作代码整体包裹 try-except 以处理异常；必须兼容 §4.4（禁止裸 `except:`，须指定异常类型）
- **正例**:
```python
def process(file_path: str):
    try:
        ...  # 业务步骤
    except FileNotFoundError as e:
        logger.error(f"文件不存在: {e}")
        return None
    except Exception as e:  # 兜底也须指定类型并记录详情
        logger.error(f"处理失败 {type(e).__name__}: {e}")
        return None
```
- **反例**: 裸 `except:` 且不指定异常类型（违反 §4.4）
- **来源**: 历史提示词提炼（T1-T48，48/48）
- **关联架构约束**: 本文档 §4 Error Handling

### [5] 关键参数为空/不存在时必须中断并抛出异常
- **优先级**: 🟡 推荐
- **要求**: 主要（必填）参数为空或不存在时立即中断并抛出异常，禁止带病继续
- **正例**:
```python
if not file_path:
    raise ValueError("file_path 为必填参数，不能为空")
```
- **来源**: 历史提示词提炼（T1-T48，≥40次）
- **关联架构约束**: 本文档 §4 Error Handling

### [6] 可选参数为空时按预设默认值处理
- **优先级**: 🟡 推荐
- **要求**: 可选参数为空时按文档约定的默认值处理，不报错
- **正例**: `skip_rows = skip_rows if skip_rows is not None else 0`
- **来源**: 历史提示词提炼（T1-T48，≥35次）
- **关联架构约束**: 无

### [7] 循环内单步失败时 continue 跳过本轮
- **优先级**: 🟢 条件

- **正例**:
```python
for i, fp in enumerate(file_list):
    try:
        dfs.append(pd.read_excel(fp))
    except Exception as e:
        logger.warning(f"第{i}轮读取失败，跳过 {fp}: {e}")
        continue  # 进入下一轮
```
- **来源**: 历史提示词提炼（T1-T48，≥8次）
- **关联架构约束**: 无
