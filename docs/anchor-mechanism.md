# 任务执行锚点记录追踪机制（规定层）

> **规定层声明**：本文档为锚点机制的规定层载体（自 AGENTS.md §7.6 迁入，2026-09-06 精简剥离）。规定层属性不变——**一经写入，非人工显式指令不得修改**。
> 经 AGENTS.md §2.5 背书具 **[约束]** 效力；机制摘要位于 AGENTS.md §7.3、锚点层位于「当前任务锚点」。

**机制说明**：本项目实行任务执行锚点记录追踪机制。Agent 在执行符合"任务"定义的操作时，必须按照以下规则实时记录任务状态与关键节点。其目的是：使 Agent 在执行任务时实时记录关键节点，形成可追溯的执行轨迹；使 Agent 在任何中断后（主动/被动/异常/会话切换/工具切换），仅凭仓库内文件即可自适应重建上下文并继续或复盘任务；不依赖任何特定 Agent 工具的内置记忆能力，将任务追踪从工具层提升到规约层。

**任务定义**：满足以下任一条件即视为"任务"，纳入本机制管控：

1. **涉及实际操作**：对非临时目录中的文件执行了创建、修改、删除、移动中的任何一项
2. **多 Agent 协作**：提示词显式要求，或 Agent 分析后实际使用了多 Agent 工作方式
3. **长任务多步骤**：Agent 决策规划的任务步骤 ≥ 5 步

> 注：临时目录（`_temp/` 等）中的操作不计入。

**运作规则**：

1. **任务开始时**：覆写锚点层摘要，在详情层创建本任务记录文件
2. **关键节点完成时**：同步更新锚点层状态标识，追加详情层记录
3. **任务结束时**：更新锚点层状态为已完成，在详情层写入关闭标识
4. **重启/继续时**：先读取锚点层和详情层记录，经"读→比→确认"三步校验后，从记录节点继续执行
5. **非任务操作**不触发本机制

**约束**：

- 锚点层永远只存最新一次任务的摘要（5 秒可读完），详情外链
- 详情层记录必须逐步追加，禁止编造或一次性全部写入
- 记录内容必须与实际执行对齐，重启时绝不直接采信记录，必须与文件实际状态交叉验证
- 规定层一经写入，非显式指令不得修改

**三层组成结构**：

| 层 | 载体 | 职责 | 更新频率 |
|----|------|------|---------|
| 规定层 | 本文档 | 机制说明与规则定义，写入后基本不变 | 仅在显式指令要求修改时变更 |
| 锚点层 | AGENTS.md「当前任务锚点」章 | 最新一次任务的 5 秒摘要（目标、状态、轮次、时间、要点、详情索引） | 每次任务开始时覆写，关键节点时更新状态；迭代任务每轮覆写并更新轮次字段 |
| 详情层 | `docs/task-records/` 目录 | 每任务一个 md 文件，逐步追加详细执行记录 | 随任务推进实时追加 |

**迭代任务定义**：同一目标下需跨多会话/多轮推进的任务（典型链条：分析 → 计划 → 预览 → 裁定 → 编码）。每轮在详情层独立建文件，锚点层以「轮次 + 前序索引」串成链，避免单轮覆写导致历史轮次上下文丢失。

**锚点层字段规范**（迭代任务在标准字段上增加 2 项）：

- `轮次`：R<n>，迭代任务必填（如"R3 · 共 ? 轮"）；单轮任务写"单轮"
- `前序轮次`：上一轮详情文件路径；首轮写"无（首轮）"

**迭代任务收尾规则**：每轮完成时锚点层状态标 `本轮完成，待续`（而非 `已完成`）；仅当任务目标整体达成时才标 `已完成`。

**详情层规范**：

- 目录：`docs/task-records/`（[docs/INDEX.md](INDEX.md) 含声明："task-records/ 为任务执行记录目录，非知识文档，不纳入知识层管辖"）
- 文件命名：`<YYYY-MM-DD>-<task-slug>.md`
- 文件结构模板：见 [TEMPLATE.md](task-records/TEMPLATE.md)（规定层仅保留指引，模板本体独立演进；新建任务记录时复制该模板填写）

**写入规则**：

| 规则 | 说明 |
|------|------|
| 逐步追加 | 每完成一个关键节点即追加对应记录，禁止一次性写入全部 |
| 禁止编造 | 只记录实际发生的事情，未执行的不写 |
| 先有后写 | 操作完成 → 记录写入，不可先写记录再执行 |
| 中断标记 | 若在某步骤中断，该步骤状态标记为 ⏸️ 并注明中断原因（若可知） |
| 续接标记 | 重启继续时，在中断步骤处追加"续接"标记，注明续接时间 |

**运作流程**：

Step-1 行为判断定性：读取锚点层判断新旧——状态为 `无` 或 `已完成` → 可能是新任务，按任务定义判断本轮是否属于任务（是→方案 A，否→方案 C）；状态为 `执行中` 或 `已中断` → 可能是已有任务延续（方案 B）。

Step-2 策略执行：

- **方案 A（新任务）**：① 覆写锚点层（目标、状态=执行中、时间、摘要、详情索引）；② 在 docs/task-records/ 创建任务记录文件，写入摘要 + 用户输入 + Agent 理解；③ 执行流程写入流程概览，各步骤标记"未执行"；④ 每完成关键节点更新锚点层状态 + 追加详情层步骤记录；⑤ 全部完成后锚点层改为 `已完成`，详情层写入关闭标识
- **方案 B（已有任务延续）**：① 读取锚点层摘要 + 详情层对应记录；② 执行"读→比→确认"三步校验（读记录声称的文件变动 → 与文件实际状态交叉验证 → 确认一致后方可继续）；③ 执行中/未开始 → 中断节点标记"续接"后继续；已完成 → 判定为复盘，消除关闭标识标记"复盘模式"，复盘结束重新关闭；④ 正常更新锚点和详情；⑤ 完成后写入新的关闭标识
- **方案 C（非任务）**：不触发本机制，直接执行指令

**关键约束**：锚点极简（5 秒读完，详情外链）；机制恒定（规定层非显式指令不得修改）；校验先于信任（重启必须读→比→确认）；实时更新（关键节点同步记录）；关注当下（锚点层只存最新任务）；禁止编造；临时目录豁免（`_temp/` 操作不触发）。
